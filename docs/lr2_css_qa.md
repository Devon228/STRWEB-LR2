## 1. Селекторы

**В1. Какие виды селекторов использованы?**

  - содержит подстроку — `a[href*="who.int"]` (`:434`).
- **Комбинации**:
  - AND (класс + атрибут) — `a.read-more[href]` (`:327`); сюда же `table.promo-table caption`;

## 2. Псевдоклассы

**В2. Динамические состояния ссылок.**
Псевдокласс — селектор состояния: он выбирает элемент не по тегу/классу, а по его положению или состоянию в момент времени (наведение, фокус, посещённость, чётность). Псевдоклассы пишутся с одним двоеточием (`:hover`), псевдоэлементы — с двумя (`::before`).

Порядок важен: `:link` (`:452`) — непосещённая, `:visited` (`:456`, фиолетовый), `:hover` (`:460`), `:active` (`:465`, момент нажатия), `:focus-visible` (`:469`, золотая обводка при навигации с клавиатуры). LVHA-порядок (`link → visited → hover → active`) гарантирует, что более поздние состояния перекрывают ранние. Для навигации свои состояния: `.site-nav a:visited` (`:720`), `.site-nav a:hover` (`:724`).

**В3. Элементы списков и таблиц по положению.**
`:first-child` (`:476`), `:last-child` (`:480`), `:nth-child()` (`:484`), `tbody tr:nth-child(even)` (`:2020`), `td:first-child` (`:505`), `td:last-child` (`:509`).

**В4. Состояния элементов формы.**
`:enabled` (`:525`) — доступное для ввода поле, `:disabled` (`:531`, серый фон + `cursor: not-allowed`) — заблокированное, `:required` (`:541`, красная полоса слева) и `:optional` (`:547`) — обязательность, `:checked` (`:553`) — выбранные радио/чекбоксы, `:out-of-range` (`:558`, красный фон) и `:in-range` (`:563`, зелёная рамка) — попадание значения в `min`/`max`, `:valid` (`:567`) и `:invalid` (`:571`) — прошло ли значение валидацию, `:placeholder-shown` (`:575`) — поле пустое (виден placeholder), `:read-only` (`:579`) — только для чтения.

Важно: `:invalid` срабатывает сразу при загрузке (пустое обязательное поле уже невалидно) — для «мягкой» подсветки после ввода существует `:user-invalid`. Заблокированное поле есть на `payment.html` (`input#promo-applied disabled`), out-of-range — на поле возраста (введите 150 и увидите красный фон).

**В5. Кавычки в зависимости от языка цитаты.**
`q:lang(ru)` (`:236`) — «ёлочки», `q:lang(en)` (`:240`) — английские кавычки; `q::before/::after` (`:244`, `:249`). Пример: русская цитата ВОЗ и `<q lang="en">` в `about.html`.

**В6. Прочие полезные псевдоклассы.**
`:empty` (`:514`) — фон пустых ячеек; `:not()` (`:541`); `details[open]` (`:1699`); `:focus-within` (`:1020`); `@media (hover: none)` (`:2248`).

## 4. Подключение шрифтов

**В11. Как подключён шрифт из службы и зачем альтернативные?**
В `base.html:17–19` — preconnect и `<link>` Google Fonts: **Montserrat** (основной), **Roboto** (альтернативный). В CSS семейство с запасными вариантами:

```css
/* style.css:48, 65 */
--font-main: "Montserrat", "Roboto", "Segoe UI", Arial, sans-serif;
body { font-family: var(--font-main); }
```

Как это работает: `<link>` загружает CSS-файл службы, внутри которого лежат `@font-face` со ссылками на файлы шрифтов (woff2/woff). Параметр `&display=swap` (`base.html:19`) — это `font-display: swap`: пока шрифт грузится, текст показывается системным шрифтом, а затем подменяется (иначе на медленной сети текст был бы невидим).

Значение `font-family` — это **стек**: браузер берёт первый доступный шрифт. Поэтому основной и альтернативный отличаются только порядком: `--font-main` начинается с Montserrat, `--font-alt` — сразу с Roboto (применён к `option/optgroup`, `:1928`).

Generic-семейства (`serif`, `sans-serif`, `monospace`, `cursive`, `fantasy`) — стандартные ключевые слова CSS, за ними стоит конкретный шрифт, который выбирает браузер/ОС; именно они гарантируют читаемость, если ни один именованный шрифт не доступен. Засечки (`serif`) придают «документный» вид (сертификат, `:52`), моноширинный (`monospace`) выравнивает цифры и код по столбцам (реквизиты, `:53`). Ключевые слова `font: caption / menu / button / small-caption` применены к компонентам формы (`:1850–1867`).

## 5. Настройка текстового фрагмента

**В12. Красная строка и красная первая буква.**
Красная строка — `text-indent: 1.8em` (`:152`) у абзацев статей, политики и «О компании»; у первого абзаца отступ снят, потому что там буквица (`:157`). Единица `em` относительна размеру шрифта: `1.8em` — это 1.8 × 16px ≈ 29px, и отступ автоматически масштабируется вместе со шрифтом.

Красную первую букву делает `p:first-of-type::first-letter` (`:160`): `float: left; font-size: 3.4em; color: var(--accent)`. Это два разных приёма: `text-indent` сдвигает первую строку целиком, `::first-letter` стилизует только первую букву; вместе их не применяют (поэтому у первого абзаца `text-indent: 0`).

**В13. Межстрочный интервал (`line-height`).**
`line-height: 1.65` (`:69`) — это расстояние между базовыми линиями соседних строк, выраженное в безразмерном множителе (1.65 × размер шрифта). Реальный «межстрочный просвет» = `line-height − font-size`, он делится поровну над и под строкой:

```
 ┌──────────────────────────┐
 │  Текст строки 1          │  ← верх полулидинга
 │──────────────────────────│  ← базовая линия (baseline)
 │   (просвет = LH − size)  │
 │──────────────────────────│  ← базовая линия строки 2
 │  Текст строки 2          │
 └──────────────────────────┘
 line-height = расстояние между соседними baseline
```

`line-height` можно задавать числом (1.65 — «умножить на размер шрифта»; наследуется как множитель и пересчитывается для каждого размера), в `px` (фиксированная высота) или в `%` (наследуется уже посчитанное значение и может «застыть»). Безразмерное число — самый предсказуемый вариант, поэтому в проекте выбран он.

**В14. Капитель (`font-variant`) и `text-transform`.**
Капитель — `font-variant: small-caps` (`:134` для h5, `:177` для имён партнёров, `:1718` для `dt` в словаре): строчные буквы отображаются уменьшенными прописными, но регистр в HTML не меняется. `font-variant` умеет больше: `all-small-caps`, `petite-caps`, `unicase`, `normal`, а `font-variant-numeric: tabular-nums` (`:1987`, и `:1517` для реквизитов) делает цифры одинаковой ширины (удобно в таблицах).

`text-transform` меняет регистр символов: `uppercase` (`:186`, заголовок сертификата и ссылки меню), `lowercase`, `capitalize` (`:180`, имена партнёров — каждое слово с заглавной) и `none`. Важно: `small-caps` и `capitalize` — разные вещи: первый меняет **начертание** букв, второй — **регистр** текста.

**В15. Интервалы между словами и символами.**
`word-spacing: 0.4em` (`:184`, заголовок сертификата) — между словами; `letter-spacing` (`:179`, `:718`) — между буквами (кернинг имён партнёров и меню).

**В16. Перенос и разрыв слов.**
`hyphens: auto` (`:192`) — браузер расставляет переносы по правилам языка, для этого нужен атрибут `lang` (`<html lang="ru">`). `overflow-wrap: break-word` (`:194`) — аварийный вариант: ломает слишком длинное слово, только если оно не влезает в строку. `word-break: break-all` ломал бы в любом месте без учёта слогов — в проекте он не используется. Тег `<wbr>` в шаблонах задаёт потенциальные точки переноса вручную. Выравнивание — `text-align: justify` (`:199`) в статьях.

## 6. Медиа-запросы

**В17. Что такое медиа-запросы, зачем они нужны и что конкретно меняется?**

**Определение.** Медиа-запрос — конструкция CSS `@media (условие) { … }`, которая применяет правила только тогда, когда условие истинно. Условие описывает характеристики окна/устройства: ширину, высоту, ориентацию, плотность пикселей, возможность наведения курсора и т.д. Внутри запроса работают обычные каскад и специфичность — правила применяются поверх базовых, но только при совпадении.

```css
/* style.css:2105, 2133 */
@media (max-width: 1024px) { .layout { flex-direction: column; } }
@media (max-width: 768px)  { .catalog-grid { grid-template-columns: 1fr; } }
```

**Зачем.** Это основа адаптивной вёрстки: один HTML и один CSS обслуживают телефон, планшет и десктоп. Без них пришлось бы держать отдельные версии сайта, а «резиновая» вёрстка умеет менять только размеры, но не структуру (число колонок, порядок блоков, отключение `sticky`).

**Виды условий в проекте:**
- по **ширине**: `min-width: 1400px` (`:2094`), `max-width: 1024px` (`:2105`), `768px` (`:2133`), `480px` (`:2187`);
- по **высоте**: `max-height: 600px` (`:2216`) — компактнее меню, сцена и прелоадер;
- по **ориентации**: `orientation: landscape` (`:2241`) — на низких альбомных экранах сцена ещё ниже;
- по **возможностям устройства**: `hover: none` (`:2248`, на тач-экранах ссылка «сайт» у партнёра видна всегда) и `prefers-reduced-motion: reduce` (`:2256`, отключение анимаций для тех, кому они мешают).

Условия комбинируются логикой `and`/`not`/`only` и диапазонами (`@media (400px <= width <= 900px)`); единицы — `px`, `em`, `rem`. В проекте выбран **desktop-first**: базовые стили — под широкий экран, затем `max-width`-запросы сужают и перестраивают.

**Что конкретно происходит при сужении окна:**
- **> 1400px** (`:2094–2103`): `.layout` расширяется до 1480px, каталог — 4 колонки;
- **≤ 1024px** (`:2105–2131`): `.layout` из `flex`-строки становится колонкой — `aside` уезжает наверх и теряет `sticky`, каталог переходит на 2 колонки, карточки новостей чуть уже (180px), статья остаётся в 2 колонки;
- **≤ 768px** (`:2133–2185`): каталог — 1 колонка, `.news-card` из строки становится колонкой, статья — 1 колонка (`column-count: 1`, `:2154`), вакансии теряют `float` (`:2158`), круглые партнёры уменьшаются до 170px, контакты перестраиваются в колонку (`:2176`), `dl` политики и данных сертификата — в одну колонку;
- **≤ 480px** (`:2187–2214`): уменьшаются `h1` и ссылки меню, сцена — 280px, у сертификата тоньше рамка и меньше водяной знак, у прелоадера скрывается подпись;
- **высота ≤ 600px** (`:2216–2239`): компактные отступы меню, сцена 220px, прелоадер без подписи;
- **landscape ≤ 520px** (`:2241–2246`): сцена 190px.

**Как показать на защите:** открыть сайт и тянуть край окна (или DevTools → Ctrl+Shift+M): на 1024px боковая панель уходит наверх, на 768px каталог становится в один столбец, новости и статья — одноколоночными.

## 7. Grid Layout и Flexbox

**В18. Где Grid и чем он отличается от Flexbox?**
Grid — двумерная сетка (строки и колонки одновременно): каталог `.catalog-grid` (`:913–914`) и списки категорий/услуг.

```css
/* style.css:913 */
.catalog-grid {
    display: grid;
    grid-template-columns: repeat(auto-fit, minmax(230px, 1fr));
    gap: 1rem;
}
```

Flexbox — одномерная раскладка по главной оси: каркас страницы `.layout` (`:763`), навигация `.site-nav` (`:692`), карточки новостей `.news-card` (`:1560`), контакты `.contact-card` (`:1734`). В контактах фото `flex: 0 1 150px` (`:1755`) — не растёт, но может ужиматься, а текст `flex: 1 1 260px` (`:1768`) растягивается и переносится (`flex-wrap: wrap`). Именно поэтому при сужении окна карточка «дышит»: сначала сжимается текст, затем блок переносится, а в media-запросе ≤768px колонка становится вертикальной (`:2176`).

**Наборы свойств.** Grid: у контейнера `grid-template-columns/rows`, `grid-template-areas`, `gap`, `justify-items`, `align-items`; у детей — `grid-column`, `grid-row`, `grid-area`. Flexbox: у контейнера `flex-direction`, `justify-content` (по главной оси), `align-items` (по поперечной), `flex-wrap`, `gap`; у детей — `flex: grow shrink basis`, `order`, `align-self`.

**Отличие по смыслу.** Grid задаёт **двумерную сетку** — вы управляете и строками, и столбцами одновременно, элементы можно размещать по клеткам. Flexbox распределяет элементы **вдоль одной линии** и позволяет им растягиваться/сжиматься (`flex-grow` / `flex-shrink` / `flex-basis`). Поэтому каталог (нужна сетка) — Grid, а ряды карточек, меню и пары «фото + текст» (нужна линия с гибкими размерами) — Flexbox. Их можно комбинировать: Grid-карточка каталога внутри использует flex-раскладку.

**В19. Где Grid при уменьшении ширины?**
`@media (max-width: 1024px) .catalog-grid { grid-template-columns: repeat(2, 1fr); }` (`:2117`), при 768px — одна колонка (`:2138`). До медиа-запросов сетка уже адаптивна сама: `repeat(auto-fit, minmax(230px, 1fr))` (`:915`) означает «создать столько колонок минимум по 230px, сколько влезет, а свободное место разделить поровну (`1fr`)» — на широком экране их 4, на среднем 2–3, на узком 1. `auto-fit` схлопывает пустые дорожки, `auto-fill` оставил бы их — это и есть разница между ними.

## 8. Позиционирование

**В20. Виды `position` и связь с родителем.**
- `static` — значение по умолчанию, смещения не действуют;
- `relative` — смещается относительно своего обычного места, остаётся в потоке: карточка последней статьи `.latest-article` (`:1026`) — она объявлена точкой отсчёта для детей;
- `absolute` — вырывается из потока и позиционируется относительно ближайшего **не-static** родителя: бейдж `.latest-article__badge` (`:1037`) внутри `relative`-карточки. Если бы у карточки не было `position: relative`, бейдж отсчитывался бы от окна/`body`, то есть вёл бы себя как `fixed`;
- `fixed` — всегда «приклеен» к краю **окна браузера** и не движется при прокрутке: прелоадер `.preloader` (`:1307`);
- `sticky` — гибрид: ведёт себя как `relative`, пока не достигнет заданного края, затем «прилипает»: навигация `.site-nav { position: sticky; top: 0; z-index: 1000; }` (`:692–695`). Именно поэтому меню остаётся на экране при прокрутке.

**Смещения и containing block.** Сдвиг задаётся свойствами `top/right/bottom/left` (или `inset`). У `relative` они сдвигают элемент от его обычной позиции (место в потоке сохраняется); у `absolute`/`fixed` — от краёв содержащего блока. Для `absolute` содержащий блок — ближайший предок с `position` ≠ `static` (relative/absolute/fixed/sticky); если такого нет — начальный содержащий блок (окно/`html`), и тогда `absolute` ведёт себя почти как `fixed`. `sticky` требует двух условий: прокручиваемый предок и хотя бы одно заданное смещение (`top: 0` в проекте).

## 9. `hidden` vs `display: none` (и `visibility`/`opacity`)

**В21. В чём разница?**
- `display: none` — элемент полностью удаляется из потока, место не занимает;
- атрибут `hidden` — семантический «скрытый» элемент, по умолчанию браузер сам применяет `display: none`; в проекте это закреплено `[hidden] { display: none !important; }` (`:656`) для блока отдела в форме регистрации;
- `visibility: hidden` — элемент невидим, но **место занимает**;
- `opacity: 0` — элемент прозрачен, но полностью участвует в раскладке и событиях.

В проекте на паре `visibility + opacity` построена ссылка «сайт» у партнёра: `.partner__site` (`:1006`) скрыта, при наведении `.partners .partner:hover .partner__site` (`:1019`) становится видимой с плавным переходом.

**Нюансы для защиты.** `display` анимировать нельзя (это дискретное свойство), а `visibility` и `opacity` — можно через `transition`, поэтому появление ссылки сделано на них. Для доступности: `display: none` и `visibility: hidden` убирают элемент и из дерева доступности (скринридер его не прочитает), `opacity: 0` — оставляет элемент кликабельным и читаемым. Атрибут `hidden` — это семантический аналог `display: none`, его можно снять из JS/HTML, не трогая CSS.

## 10. `float` и `clear`

**В22. Где плавающие блоки и зачем `clear`?**
`float` вынимает элемент из обычного потока и прижимает его к краю строки, а текст и инлайн-содержимое его обтекают — так до Flexbox/Grid делали многоколоночные макеты. Особенность: родитель «не видит» высоту плавающих детей (высота контейнера схлопывается), поэтому обтекание нужно закрывать.

Вакансии: `.vacancy { float: left; width: calc(50% - 1rem); }` (`:1790`). Нечётные карточки начинают новый ряд и запрещают обтекание слева — `.vacancy:nth-child(odd) { clear: both; }` (`:1809`). После списка стоит `<p class="clear">` с `.clear { clear: both; }` (`:1813`) — он «закрывает» обтекание и не даёт подвалу наехать на карточки. `clear` отменяет действие `float` с указанной стороны (`left`, `right`, `both`); классическая альтернатива — `overflow: hidden` или `.clearfix::after { content: ""; display: block; clear: both; }` у родителя.

## 11. Таблицы

**В23. Как убраны двойные границы, оформлены заголовок, пустые ячейки и выравнивание?**
У таблиц две модели границ. По умолчанию `border-collapse: separate` — у каждой ячейки своя рамка, между ними зазор `border-spacing`, и соседние рамки выглядят как двойная линия. `border-collapse: collapse` (`:1957`) заставляет соседние ячейки делить одну общую границу — двойные линии исчезают; `border-spacing: 0` (`:1958`) убирает зазоры (в схеме `collapse` он не действует, но оставлен для порядка).

`caption-side: top` (`:1993`) ставит `<caption>` над таблицей (это значение по умолчанию, но задано явно). Пустые ячейки получают штриховку через `td:empty` (`:514`) — видно в `tfoot` таблицы промокодов; `empty-cells: show` (`:1985`) разрешает им отрисовываться. Выравнивание: `text-align` (`:2033` для числовых колонок, по умолчанию — влево), `vertical-align: middle` (`:2006`), положение таблицы — `margin: 0 auto` (`:1956`). Строки/столбцы: `thead th` (`:2010`, градиентная шапка), `tbody tr:nth-child(even)` (`:2020`, зебра), `tbody tr:hover` (`:2024`, подсветка строки), `colgroup col:first-child` (`:2043`, фон первого столбца корзины).

## 12. `details`/`summary`

**В24. Как оформлен словарь терминов?**
`<details>/<summary>` — встроенный HTML-аккордеон: `<summary>` всегда виден и кликабелен, остальное содержимое показывается при открытии, без JS. Стилизация: `.faq` (`:1665`) — карточка с рамкой и тенью; `.faq summary` (`:1680`) — кликабельная строка с `cursor: pointer`; стандартный треугольник убран (`summary::marker`, `::-webkit-details-marker`) и заменён своим маркером `summary::before` с символами ➕/➖ (`:1689`); `details[open] summary` (`:1699`) меняет фон и цвет. Переходы плавные (`transition`).

## 13. Прелоадер

**В25. Что такое прелоадер и как он сделан?**
Прелоадер — лёгкая анимация, которая занимает пользователя во время загрузки и показывает, что сайт «живой». По условию ЛР2 он расположен **внизу** страницы: `.preloader` (`:1307`) — `position: fixed; bottom: 0; z-index: 1200`. «Вращающаяся пилюля» — это обычный `span` `.pill` (`:1325`): `border-radius: 999px`, две цветные половины через `linear-gradient`, разделитель — `::after`; вращение задано `@keyframes pill-spin` (`:2321`), `animation-iteration-count: infinite` (`:1333`). Для доступности у блока `role="status"` и `aria-label`. Скрипты для прелоадера не используются, только CSS.

## 14. Анимация и трансформация

**В26. Чем отличается `transition` от `animation`?**
`transition` — «лёгкая версия» анимации: плавно интерполирует изменение свойства между двумя состояниями (обычным и изменённым, например при `:hover` или `:focus`). Запускается событием, задаётся у самого элемента (`transition: transform 0.3s ease`), `@keyframes` не нужны. `animation` — «сценарий во времени»: последовательность ключевых кадров `@keyframes` с любым числом состояний, запускается автоматически при появлении элемента, может повторяться, иметь задержку и направление; управляется свойствами `animation-name`, `duration`, `timing-function`, `delay`, `iteration-count`, `direction`, `fill-mode`, `play-state`.

**В27. Что означают 0 % и 100 % и как сделать анимацию бесконечной?**
0 % — начальное состояние кадра, 100 % — конечное; между ними можно задавать промежуточные (50 %, 30 % и т.д.). Запись `0%`/`100%` равнозначна `from`/`to`; состояния можно группировать через запятую (`0%, 52% { … }` — значение удерживается). Бесконечность — `animation-iteration-count: infinite` (в шорткате просто `infinite`, `:1333`); чтобы после окончания элемент остался в последнем кадре, добавляют `animation-fill-mode: forwards`. В сцене аптеки ключевые кадры 0/30/55/80/100 % задают маршрут покупателя (`:2342`).

**В28. Какие трансформации бывают и где 3D?**
2D-функции: `translate(x, y)` — сдвиг, `scale(kx, ky)` — масштаб, `rotate(deg)` — поворот, `skew(deg)` — наклон, `matrix(...)` — всё сразу. 3D-функции: `translate3d`, `translateZ`, `rotateX/rotateY/rotateZ`, `rotate3d(x, y, z, angle)`. Чтобы 3D выглядело объёмным, родителю задают `perspective` (глубину) и/или `transform-style: preserve-3d`; `transform-origin` задаёт точку вращения/масштаба (по умолчанию центр). Несколько функций пишутся через пробел и применяются слева направо. 3D в проекте: `perspective` сцены (`:1085`), `rotate3d` лекарства (`:2383`), `perspective(700px) rotateY(...)` у логотипа (`:1360`) и партнёров (`:965`). Анимация сцены: `customer-walk` (`:2342`), `customer-straighten` (`:2360`), `scarf-fade` (`:2369`), `medicine-fly` (`:2378`), `smile-show` (`:2402`), `name-appear` (`:2413`), моргание `blink` (`:2333`).

**В29. Что можно указать в свойстве `animation` (шорткат)?**
`animation: name duration timing-function delay iteration-count direction fill-mode play-state`. Порядок в шорткате: первым — имя (`none`, если нет), затем длительность, функция плавности, задержка, число повторов, направление (`normal/reverse/alternate`), режим заполнения (`none/forwards/backwards/both`), состояние (`running/paused`). В проекте: `animation: pill-spin 1.6s linear infinite;` (`:1333`), `animation: name-appear 12s cubic-bezier(0.22, 1, 0.36, 1) infinite;` (`:1297`).

Функции плавности: `linear` — равномерно; `ease` — разгон и торможение (по умолчанию); `ease-in` — только разгон; `ease-out` — только торможение; `ease-in-out` — разгон и торможение; `cubic-bezier(x1, y1, x2, y2)` — своя кривая Безье; `steps(n)` — «ступеньками» (для кадровой анимации). Живая кривая Безье есть также в наведении на партнёра — `transition: … cubic-bezier(0.34, 1.56, 0.64, 1)` (`:962`, лёгкий «отскок»).

## 15. Градиенты

**В30. Какие виды градиентов использованы?**
- `linear-gradient(направление, цвет1, цвет2, …)` — фон сайта (`:80`), меню, кнопки, шапки таблиц; цвет задаётся под углом (`160deg`) или ключевыми словами (`to right`);
- `radial-gradient(форма, цвет1, цвет2)` — фон body и круглых блоков партнёров (`:79`, `:951`); можно задавать центр и форму (`circle at 30% 25%`);
- `conic-gradient(от угла, цвета)` — бейдж «Последняя статья» (`:1044`), цвета идут по кругу.

Поддерживаются несколько цветовых стопов, проценты и `transparent` — так строятся мягкие переходы и «прозрачные» края. Градиент — это значение `background-image`, поэтому он комбинируется с картинками (несколько фонов через запятую, как у `body`, `:78–80`) и может анимироваться.

## 16. z-index и слоистость сертификата

**В31. Что такое `z-index`?**
`z-index` задаёт порядок наложения элементов по оси Z внутри одного контекста наложения. Большее число — выше в стеке; при равных значениях выше тот, кто в коде позже. Работает только у позиционированных элементов (`relative/absolute/fixed/sticky`) или у детей flex/grid-контейнеров — на `static` он игнорируется. Важно: элемент с `position` и `z-index` создаёт **свой контекст наложения**, и «перепрыгнуть» через его границу нельзя (вложенный с `z-index: 9999` не окажется выше внешнего с `z-index: 10`). Пример — сертификат (`about.html`), три слоя:
1. `.certificate::before` (`:1383`, `z-index: 1`) — водяной знак-печать;
2. `.certificate::after` (`:1397`, `z-index: 2`) — глянцевый градиент;
3. `.certificate__content` (`:1406`, `z-index: 3`) — текст поверх.
Плюс отдельные z-index: бейдж статьи (`:1041`), sticky-меню 1000 (`:695`), прелоадер 1200 (`:1312`).

## 17. Курсор

**В32. Как меняется курсор при наведении на кнопку?**
`a, button, summary, input[type=submit], input[type=button], label[for] { cursor: pointer; }` (`:653`); у заблокированных полей `cursor: not-allowed` (`:538`), у аббревиатур `cursor: help` (`:276`).

## 18. Трансформация логотипа

**В33. Что происходит с логотипом при наведении?**
`.company-logo:hover` (`:1359`) поворачивает логотип в 3D и увеличивает:

```css
/* style.css:1359 */
.company-logo:hover {
    transform: perspective(700px) rotateY(18deg) rotate(-3deg) scale(1.12);
}
```

Переход задан `transition: transform 0.5s ease` (`:1356`).

## 19. Многоколоночная вёрстка («как газета»)

**В34. Где многоколоночный макет?**
Полный текст новости — `.article-content` (`:1648`): `column-count: 2`, `column-gap: 2.4rem`, разделитель `column-rule` (`:1655`). При ширине ≤768px — одна колонка (`:2154`). Текст при этом выровнен по ширине с переносами (`:198–199`), а первая буква — буквица (`:160`).

## 20. overflow, многоточие, списки, скругления, схлопывание

**В35. Как обрезается текст с многоточием?**
Для однострочного многоточия нужны четыре условия: элемент должен быть блочным, `white-space: nowrap` (запрет переноса), `overflow: hidden` (обрезать лишнее) и `text-overflow: ellipsis` (нарисовать «…»). В проекте так сделан заголовок новости (`:1600–1603`).

Для многострочного варианта стандартного свойства пока нет — используется `-webkit-line-clamp` вместе с `display: -webkit-box` и `-webkit-box-orient: vertical`; `-webkit-line-clamp: 3` ограничивает текст тремя строками и ставит многоточие (`:1607–1611`). Дополнительно задан `max-height: 4.8em` как страховка для браузеров без `line-clamp`. Такой же приём — у описания партнёра (`:996`).

**В36. Как оформлены списки?**
`list-style: none` убирает стандартные маркеры (`:603`), затем свои маркеры через `::before` (`:606`) и `::marker` (`:611`). Архив промокодов — с зелёными галочками и красными крестиками (`:611–620`).

**В37. Как задаются скруглённые углы?**
`border-radius`: у кнопок и пилюль `999px` (`:1009`, `:1330`), у круглых партнёров `50%` (`:958`), у карточек `var(--radius)` (`:45`).

**В38. Что такое схлопывание margin?**
Вертикальные `margin` соседних блоков не суммируются, а схлопываются: у двух абзацев с `margin-bottom: 1em` между ними будет 1em, а не 2em (`:143`). Схлопывание работает в трёх ситуациях: между соседними блоками (берётся больший из двух отступов), между родителем и его первым/последним ребёнком (если у родителя нет `padding`, `border` и `overflow`), и у пустого блока (его собственные верхний и нижний margin схлопываются). Предотвращают схлопывание `padding`, `border`, `overflow: hidden` (создаёт BFC) или `display: flex/grid` у родителя. В проекте у абзацев задан только нижний отступ, а расстояния секций регулируются `padding` и `border` — поэтому «двойных» отступов нет.

## 21. Вендорные префиксы

**В39. Что это и где использованы?**
Вендорные префиксы — приставки `-webkit-` (Chrome/Safari), `-moz-` (Firefox), `-ms-` (IE/Edge), `-o-` (Opera) для свойств, которые старые браузеры понимают только с приставкой. Браузеры игнорируют незнакомые им свойства, поэтому дублирование безопасно. В проекте: `-webkit-border-image`/`-moz-border-image` для рамки сертификата (`:2271–2273`), `-webkit/-moz/-ms-transform` (`:2276`), `-webkit/-moz/-o-animation` (`:2284`), `-webkit-column-count` (`:2291`), `-webkit-line-clamp` (`:2297`), `-webkit-hyphens` (`:192`).

Сейчас большинство свойств префиксов уже не требует, но `-webkit-` по-прежнему нужен для `line-clamp`, `background-clip: text` и части мобильных браузеров. В реальных проектах префиксы не пишут руками — их расставляет Autoprefixer (PostCSS) по данным caniuse.
