# ЛР3 — короткие вопросы по JavaScript в виде карточек

Формат: выражение → что выведет → почему. В конце каждой группы — общее правило. Проверено в Firefox; для спорных карточек отмечено, если комментарий в методичке неточен.

---

## Группа «Булевы операции»

### Карточка 1

```js
let x;
console.log(0 || 1 && 2 || x=8); // 2
console.log(x);                  // undefined
```

**Важно.** В таком виде без скобок это **SyntaxError: invalid assignment left-hand side**: приоритет `=` ниже, чем у `||`, поэтому JS пытается присвоить значение выражению `0 || 1 && 2 || x`. В методичке подразумевалось `0 || 1 && 2 || (x = 8)`. Тогда:

- `&&` выполняется раньше `||`: `1 && 2` → `2`;
- `0 || 2` → `2` (левое `0` ложно, берётся правое);
- `2 || (x = 8)` → `2`; правое не вычисляется из-за **короткого замыкания**;
- `x` остаётся `undefined`.

**Вывод:** `2`, затем `undefined` (при наличии скобок вокруг `x = 8`).

### Карточка 2

```js
let x;
console.log(1 || 2 && 5 || 0); // 1
console.log(x);                // undefined
```

`&&` раньше `||`: `2 && 5` → `5`; `1 || 5` → `1`; дальше `|| 0` уже не вычисляется. `x` не участвует и остаётся `undefined`.

### Карточка 3

```js
let a;
true || (a = 1);
alert(a); // undefined
```

`true || ...` — короткое замыкание, правая часть `(a = 1)` не выполняется. `a` объявлена через `let`, но не инициализирована → `undefined`.

### Карточка 4

```js
console.log(2 && 1 && null && undefined); // null
```

`&&` возвращает первый **ложный** операнд: `2` истинно → идём к `1`, оно истинно → идём к `null`, оно ложно → возвращаем `null`; до `undefined` дело не доходит.

**Общее правило булевой группы.** `&&` и `||` возвращают не `true/false`, а один из операндов. `&&` имеет более высокий приоритет, чем `||`. Вычисление ленивое: правая часть не выполняется, если результат уже определён. «Ложные» значения: `false`, `0`, `-0`, `0n`, `""`, `null`, `undefined`, `NaN`.

## Группа «Другие операции»

### Карточка 1

```js
let a = (1, 5 - 1, 2) * 2;
console.log(a); // 4
```

Запятая — оператор: значение выражения — **последний** операнд. `(1, 5 - 1, 2)` → `2`; `2 * 2` → `4`.

### Карточка 1.5

```js
let a = (1, 5 + 1, 2) * 2;
console.log(a); // 4
```

`5 + 1` вычисляется, но результат отбрасывается; последний операнд — `2`; `2 * 2` → `4`.

### Карточка 2

```js
console.log((1, 2 + 1) * 2); // 6
```

`2 + 1` → `3` (последний операнд запятой); `3 * 2` → `6`.

### Карточка 3

```js
console.log(null * 32); // 0
```

В арифметике `null` приводится к `0`: `0 * 32` → `0`.

### Карточка 3.5

```js
var a = null * 32;
console.log(a); // 0
```

То же самое: `null → 0`, результат `0` присваивается `a`.

### Карточка 4

```js
console.log([] + false - null + true); // NaN
```

1. `[] + false` — `+` видит объект/строку, `[]` превращается в `""`, `false` — в `"false"`, получается строка `"false"`.
2. `"false" - null` — `-` всегда приводит к числу: `Number("false")` → `NaN`, `null` → `0`, итог `NaN`.
3. `NaN + true` → `NaN + 1` → `NaN`.

### Карточка 5

```js
console.log(true + false); // 1
```

`+` с двумя логическими значениями приводит их к числам: `1 + 0` → `1`.

### Карточка 6

```js
var x = 5;
alert(x+++1); // 6
alert(x++);   // 6
```

`x+++1` читается как `(x++) + 1`: сначала возвращается старое `x = 5`, потом `x` становится `6`; `5 + 1` → `6`. Второй `x++` возвращает уже `6`, после чего `x` становится `7`. В `alert` оба раза `6`.

### Карточка 7

```js
alert("груша" > "яблоко"); // false
```

Строки сравниваются посимвольно по Unicode-кодам. `"г"` (U+0433) меньше `"я"` (U+044F), поэтому `"груша" > "яблоко"` — `false`.

### Карточка 8

```js
alert(10e-1["toString"](2)); // 1
```

`10e-1` — числовой литерал `1`. `1["toString"](2)` вызывает метод числа с основанием 2: `1` в двоичной системе — `"1"`. `alert` показывает `1`.

### Карточка 9

```js
alert(20e-1["toString"](2)); // в методичке «2», фактически 10
```

`20e-1` — число `2`. `(2).toString(2)` — это `"10"` (двойка в двоичной системе), а не `2`. `alert` покажет **10**. Комментарий `// 2` в карточке неточен: либо там должно было быть `toString()` без основания, либо ожидалось другое выражение.

**Общее правило группы.** Сначала работает приоритет операторов: запятая ниже присваивания, `*` выше `+`, `+` выше сравнения. `+` — единственный «строковый» арифметический оператор: если хотя бы один операнд строка (или объект, приводящийся к строке), будет конкатенация. `-`, `*`, `/`, `%` всегда приводят к числу. `alert`/`console.log` показывают строковое представление результата.

## Группа «Новое свойство»

### Карточка 1

```js
let str = {"Hello"} // Ошибка, SyntaxError: Unexpected string
str.something = 5
alert(str.something)
```

В объектном литерале после строки нужно двоеточие: `{"Hello": ...}`. Одиночная строка без ключа — синтаксическая ошибка, код до выполнения не дойдёт.

### Карточка 2

```js
let str = {tr: "Hello"};
str.something = 5;
alert(str.something); // 5
```

Объект — изменяемая структура; свойство `something` добавляется, значение `5` сохраняется.

### Карточка 3

```js
let str = "Hello World";
str.something = 5;
alert(str.something); // undefined
```

Строка — примитив. В нестрогом режиме попытка записать свойство в примитив молча игнорируется (создаётся временный объект-обёртка, который сразу выбрасывается). В строгом режиме (`'use strict'`) была бы `TypeError`. Свойства нет → `undefined`.

**Общее правило.** Объекты хранятся по ссылке и мутабельны; примитивы (`string`, `number`, `boolean`, `null`, `undefined`, `symbol`, `bigint`) неизменяемы — «свойства на примитиве» не сохраняются.

## Группа «Неклассифицируемо»

### Карточка 1

```js
console.log(new Date()); // текущая дата/время
```

Например: `Mon Nov 17 2025 11:18:40 GMT+0300`. `new Date()` создаёт объект текущего момента; в консоли он отображается как читаемая строка, а не «timestamp» в смысле числа (для числа нужен `Date.now()`).

### Карточка 2

```js
console.log("156"[0]); // "1"
```

Строка — последовательность символов; `[0]` — первый символ. Тип результата — строка `"1"` (в консоли может выглядеть как `1`).

### Карточка 3

```js
console.log("1"[0]); // "1"
```

Первый символ строки `"1"` — сама `"1"`.

## Группа `parseInt`

### Карточка 1

```js
console.log(parseInt("$1.2")); // NaN
```

`parseInt` пропускает пробелы, затем читает цифры **с начала** строки. Первый непробельный символ `$` — не цифра, поэтому `NaN`.

### Карточка 2

```js
console.log(parseInt("0 минут")); // 0
```

Первый символ `0` — цифра; дальше пробел и буквы, разбор останавливается. Результат `0`.

### Карточка 3

```js
parseInt("1px") // 1
```

Читает `1`, на `p` останавливается → `1`.

**Общее правило.** `parseInt(string, radix)` читает целое число с начала строки; если первый значимый символ не цифра (и не `+`/`-`) — `NaN`. Второй аргумент — система счисления, всегда указывайте `10` для десятичной. `Number("1px")`, в отличие от `parseInt`, даст `NaN` (он требует корректного числа целиком).

## Группа `Array`

### Карточка 1

```js
let a = new Array(1, 2); // [1, 2]
let b = new Array(3);    // [ <3 empty items> ]
console.log(a[0] + b[0]); // NaN
```

`new Array(1, 2)` — массив из двух элементов. `new Array(3)` с одним числовым аргументом создаёт массив длины 3 с пустыми слотами; `b[0]` — `undefined`. `1 + undefined` → `NaN`.

### Карточка 2

```js
let a1 = [1, 2, 3];
let a2 = [1, 2, 3];
alert(a1 == a2); // false
```

Массивы — объекты; `==` сравнивает ссылки, а не содержимое. Две разные ссылки → `false`. Для сравнения содержимого нужен `JSON.stringify`, поэлементное сравнение или `Array.prototype.every`.

### Карточка 3

```js
let a = Array();
a[a.length] = 0;
a[a.length] = 1;
alert(a.length); // 2
```

`a.length` сначала `0`: `a[0] = 0`, длина становится `1`; затем `a[1] = 1`, длина `2`.

### Карточка 4

```js
var a = [10, 20, 30, 40, 50];
var b = a.slice(1, 3);
console.log(b); // [20, 30]
```

`slice(start, end)` берёт элементы с индекса `start` до `end` **не включая**; исходный массив не меняется.

### Карточка 5

```js
let a = [];
a[0] = 10;   // [10]
a[10] = 100; // [10, empty × 9, 100]
delete a[10]; // [10, empty × 10]
console.log(a.length); // 11
```

`delete` удаляет значение, но **не сдвигает** массив и не уменьшает `length`. Длина определяется последним использованным индексом: после `a[10]` она равна `11` и остаётся такой после `delete`.

### Карточка 6

```js
let a = [1, , , , 5];
alert(a.join("+")); // 1++++5
```

В массиве 5 позиций: `1`, три пустых слота, `5`. `join` превращает каждый пустой слот в пустую строку: `1` + `+` + `` + `+` + `` + `+` + `` + `+` + `5` → `1++++5`.

### Карточка 7

```js
var a = [10, 20, 30, 40, 50];
var b = a.slice(1);
console.log(b); // [20, 30, 40, 50]
```

Если второй аргумент `slice` не указан, берётся до конца массива.

**Общее правило.** Массив — объект с числовыми индексами и `length`. `length` не всегда равна количеству реальных элементов (разреженные массивы). `slice` не мутирует, `splice` мутирует. `delete` оставляет «дырку» и не меняет длину; для удаления элемента обычно используют `splice`, `filter` или `pop/shift`.

## Группа `Type Cast` (приведение типов)

### Карточка 1

```js
let a = {toString: function() { return '1'; }};
alert(1 + a + 1); // 111
```

`+` с объектом вызывает `ToPrimitive`: `a` превращается в строку `"1"`. `1 + "1"` → `"11"` (конкатенация), `"11" + 1` → `"111"`.

### Карточка 2

```js
let a = {toString: function() { return 3; }};
alert(1 + a + 1); // 5
```

`a` приводится к числу `3` (потому что `toString` вернул число). `1 + 3` → `4`, `4 + 1` → `5`.

### Карточка 2.1

```js
let a = 1;
let b = {toString() { return 3; }};
let c = 1;
console.log(a + b + c); // 5
```

`a + b` → `1 + 3` → `4`, затем `4 + c` → `5`.

### Карточка 3

```js
let a = prompt("Введите число"); // 5
let b = a + 1;
alert(b); // "51"
```

`prompt` всегда возвращает строку (или `null`). `"5" + 1` — конкатенация → `"51"`. Чтобы получить число: `Number(a) + 1` или `+a + 1`.

### Карточка 4

```js
var a = [1];
var b = a.concat(2, 3);      // [1, 2, 3]
var c = a.concat([2, 3]);    // [1, 2, 3]
```

`concat` добавляет аргументы; массив-аргумент разворачивается на один уровень. Поэтому `b` и `c` одинаковы.

**Общее правило.** `+` сначала пытается привести объект к примитиву (`valueOf`, затем `toString`); если хотя бы один операнд стал строкой — конкатенация, иначе сложение чисел. `-`, `*`, `/` всегда дают число. `prompt`/`value` из input — строки; приводите явно.

## Группа «Необъявленная переменная»

### Карточка 1

```js
console.log(a + b + c); // NaN
var a = 10;
var b = 15;
var c = 20;
```

`var`-объявления **поднимаются** (hoisting) в начало функции/скрипта, но инициализация остаётся на месте. На момент `console.log` переменные уже существуют, но равны `undefined`: `undefined + undefined + undefined` → `NaN`. После присваивания `a + b + c` было бы `45`.

Если бы `var` не было вовсе, обращение к неизвестному имени дало бы `ReferenceError: a is not defined` (а не `NaN`). С `let/const` была бы temporal dead zone — тоже `ReferenceError` до объявления.

**Общее правило.** `var` hoisted → `undefined`; `let/const` hoisted, но в TDZ → `ReferenceError`; необъявленная переменная в non-strict режиме при **записи** создаёт глобальную (`window.x`), при **чтении** — `ReferenceError`.

## Супер-короткая шпаргалка

| Выражение | Результат |
|---|---|
| `0 || 2` | `2` |
| `1 && 2` | `2` |
| `null * 32` | `0` |
| `true + false` | `1` |
| `[] + false - null + true` | `NaN` |
| `"5" + 1` | `"51"` |
| `Number("5") + 1` | `6` |
| `"1"[0]` | `"1"` |
| `parseInt("1px")` | `1` |
| `parseInt("$1")` | `NaN` |
| `[1,2] == [1,2]` | `false` |
| `new Array(3).length` | `3` |
| `[1, , 5].join("+")` | `1++5` |
| `20e-1["toString"](2)` | `"10"` |
